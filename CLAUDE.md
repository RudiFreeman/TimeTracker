# Portable Time Tracker — заметки для разработки

Десктопный трекер времени для Windows и macOS (solo video editor / content producer). Код один, сборки две — см. «Mac». Исходные требования — [docs/PRD.md](docs/PRD.md).
Пользователь общается по-русски; весь UI на русском (кроме подзадачи по умолчанию «Without task» — так в PRD).

## Запуск и сборка
- Из исходников: `pip install -r requirements.txt` → `python main.py` (Python 3.13, PySide6-Essentials).
- Сборка: `build.bat` → `dist\TimeTracker.exe` (PyInstaller `--onefile --windowed`, ~35 МБ). `build/`, `dist/`, `*.spec` — артефакты.
- База `timetracker.db` (SQLite) создаётся рядом с .exe (`db.app_dir()`: папка exe при frozen, иначе корень проекта).
- Одна копия на папку — именованный mutex в [main.py](main.py) (Mac: `fcntl.flock` на `.timetracker.lock` в папке данных).
- Git: публичный репозиторий https://github.com/RudiFreeman/TimeTracker, ветка `main`, push по HTTPS (SSH не настроен — пользователь хочет разобраться позже). Автор коммитов — `Aleksei Rudovich <31577017+RudiFreeman@users.noreply.github.com>` (локальный git config; gmail в публичный репо не светить). В репо не идут база, `backups/`, `build/`, `dist/`, `release/v*/` (см. .gitignore). Коммитить и пушить — когда пользователь просит; каждый выпуск версии — отдельный коммит «Time Tracker vX.Y.Z».
- Раздача коллегам: `build.bat` в конце запускает [release.py](release.py), он кладёт сборку в `release/vX.Y.Z/` (номер из `__version__`): папка `TimeTracker/` и архив `TimeTracker-X.Y.Z.zip` **с одинаковым содержимым** — exe + README.txt + UPDATE.txt (копии шаблонов из корня `release/`, имена именно такие — по просьбе пользователя). Один архив и на новую установку, и на обновление. Больше ничего в папке версии нет (так решил пользователь). Любое изменение для коллег = новая папка версии. Папка внутри архива без номера — у коллег она постоянная, рядом лежит их база. Если папка версии уже есть, она перезаписывается с предупреждением. Базу в архивы не класть. В .bat — только латиница в комментариях.

## Версии
- **Текущая версия: v2.4.0.** Единственный источник — `__version__` в [timetracker/__init__.py](timetracker/__init__.py) (показывается на странице «О программе»). Нигде больше номер не хардкодить (в README/README.txt/UPDATE.txt номера быть не должно; в README.md версия — значок shields.io из GitHub releases/latest, зелёный, обновляется сам; остальные значки синие, номера библиотек в них — X.Y без патча, иначе test_version упадёт). При выпуске номер вручную меняется ещё в трёх местах — верхняя запись и строка «Текущая версия» в CHANGELOG.md, «Текущая версия» и строка «История» здесь; `tests/test_version.py` сверяет их все с `__version__` и не даст собрать выпуск с расхождением.
- [CHANGELOG.md](CHANGELOG.md) вшит в exe (`--add-data` в build.bat) и показывается в «О программе» → «Что нового» (всё от первого `## `). Поэтому записи пишутся **для пользователя**: простыми словами, без имён файлов, таблиц и кода. Заголовок версии: `## X.Y.Z — ДД.ММ.ГГГГ`.
- Нумерация `MAJOR.MINOR.PATCH`:
  - **MAJOR** — переписывание программы или изменение базы, несовместимое со старыми версиями (v1 tkinter → v2 PySide6);
  - **MINOR** — новая заметная функция (учёт токенов = 2.1.0);
  - **PATCH** — исправления и мелкие доработки без новых функций.
- Версия поднимается **при выпуске** (сборка exe + обновление архивов в `release/`), а не при каждой правке. Порядок выпуска: поднять `__version__` → запись в [CHANGELOG.md](CHANGELOG.md) (новые сверху, дата, что изменилось простыми словами, отметка если менялась схема БД) → строка «Текущая версия» здесь → `python -m pytest` (все зелёные) → строки версии в таблице «Проверка на Windows и Mac» → коммит «Time Tracker vX.Y.Z» + тег `vX.Y.Z` → push ветки и тега (с разрешения пользователя) → GitHub сам соберёт обе версии и черновик релиза → пользователь проверяет файлы из черновика на Windows и Mac ([tests/QA_CHECKLIST.md](tests/QA_CHECKLIST.md): раздел 0 + затронутые, ⬜ → ✅) → публикация черновика (по просьбе пользователя). Название релиза «Time Tracker X.Y.Z». На Windows `gh` не установлен — там релиз правится через REST API с токеном из `git credential fill` (scope repo), токен не печатать. Скачать последнюю версию: https://github.com/RudiFreeman/TimeTracker/releases/latest
- **Выпуск собирает GitHub** ([.github/workflows/build.yml](.github/workflows/build.yml), с 2.4.0): каждый push — тесты + сборка Windows (`build.bat` на windows-latest → `.zip`) и Mac (`build_mac.sh` на macos-14 → `.dmg`), артефакты `TimeTracker-windows` / `TimeTracker-mac` / `screenshots`. Push тега `vX.Y.Z` (тег = `__version__`, иначе сборка падает) → **черновик** релиза с обоими файлами, текст — [tools/release_notes.py](tools/release_notes.py) (Скачать / Установка / Обновление / «⚠ Не проверено» / «## Что нового» из CHANGELOG). Черновик автообновление не видит; публикует пользователь сам или просит Claude (`gh release edit vX.Y.Z --draft=false`, перед этим убрать раздел «⚠ Не проверено», когда всё проверено). Опубликованный релиз сборка не трогает. Локальный `build.bat` / `build_mac.sh` — для проверки до выпуска. На Mac `gh` есть и авторизован.
- **Таблица «Проверка на Windows и Mac»** в начале [tests/QA_CHECKLIST.md](tests/QA_CHECKLIST.md): каждое заметное изменение → строка `| версия | что проверить | ⬜ | ⬜ |` (Claude добавляет сам вместе с изменением; `н/п` — к системе не относится). Пользователь ставит `✅` по мере проверки на своей системе; всё `⬜` текущей версии попадает в черновик релиза. Формат стережёт `tests/test_release_notes.py`.
- В релизе два файла: Windows `TimeTracker-X.Y.Z.zip` (из build.bat) и Mac `TimeTracker-X.Y.Z-mac.dmg` (оба кладёт в черновик сборка GitHub по тегу). ⚠ Mac-файл — только `.dmg`, **никогда не `.zip`**: Windows-версии до 2.3.2 берут первый `.zip` релиза (`test_updater.py` это стережёт). Mac-файл можно догрузить в уже опубликованный релиз: без `.dmg` Mac-программы обновление просто не видят.
- **GitHub Release = канал автообновления** (с v2.2.0, см. «Автообновление»): программы коллег сами видят новый релиз. Поэтому: тег строго `vX.Y.Z`, релиз опубликован (не draft/prerelease — `releases/latest` их не видит), zip — единственный `.zip` в Assets и внутри есть `TimeTracker/TimeTracker.exe`, dmg — единственный `.dmg`, в корне `TimeTracker.app`, в описании заголовок `## Что нового` (всё после него показывается в окне обновления). Выложенный релиз сразу уйдёт всем — публиковать только проверенную сборку.
- Если сборка — только исправление уже выпущенного, это PATCH (2.1.0 → 2.1.1).

## Обязательные правила работы
1. **Версии ведутся всегда.** Любая сборка exe для себя или коллег = выпуск: перед `build.bat` поднять `__version__` по правилам выше и дописать запись в CHANGELOG.md. Пересобрать exe с тем же номером можно, только если новая сборка ещё никому не отдавалась. Если изменения накоплены, а номер не поднят, Claude напоминает об этом перед сборкой.
2. **Идеи пользователя на будущее — [docs/IDEAS.md](docs/IDEAS.md)** (Mac, обратная связь, общий отчёт, задачи от начальника, Битрикс24, аналитика, помидор, обучение, прокрутка списков, компактный режим, место базы, импорт CSV): варианты, ничего не решено. Новые идеи дописывать туда.
   **Журнал наблюдений — [docs/CODE_NOTES.md](docs/CODE_NOTES.md).** Заметил по ходу работы странность или техдолг не по текущей задаче — не чини на месте, добавь запись (реестр + детали). Разбираешь долг — бери записи `🔴 open` оттуда.
3. **Тесты перед выпуском** — [tests/README.md](tests/README.md): `python -m pytest` зелёный до `build.bat`, потом ручной [tests/QA_CHECKLIST.md](tests/QA_CHECKLIST.md). Новая функция/исправленный баг → тест (или пункт чеклиста, если автотестом не проверить); недостающее — в «🔴 Нужно покрыть». Реестр «Что уже покрыто» держать актуальным.
4. После каждой заметной доработки обновлять этот файл (структура, правила UI), чтобы следующая сессия начиналась с актуальной картины.

## Модель данных
`products` → `sessions` (product_id, subtask_id, status active|paused|stopped) → `intervals` (start, end NULL пока идёт, last_seen, after_hours). Плюс `subtasks`, `settings` (key/value: limit_enabled, limit_time, day_start, topmost, position, mini_position, last_product, last_subtask).
- `token_usage` (product_id, model, tokens, created_at) — расход токенов AI-сервисов (ElevenLabs и т.п.), привязан к продукту и времени записи, не к сессии. Модель — свободный текст; `db.add_tokens()` приводит написание к уже существующему (casefold). Ввод — кнопка-калькулятор справа от больших цифр таймера (слева симметричный отступ, чтобы цифры были по центру); в строках списка открытых сессий слева от времени — сумма токенов продукта (`paint_entry(tokens_text=...)`) (`dialogs.TokenDialog`, Enter в полях = следующее поле, Enter в количестве = сохранить). Под полями — история записей продукта из поля (итог по моделям, двойной клик — взять модель, ПКМ — удалить); диалог получает колбэки `history`/`delete`, сам к БД не обращается. Показ — колонка «Токены» в Сводке: продукт → модель → отдельные записи (ПКМ — удалить). В журнал и CSV токены не выводятся (по решению пользователя).
- Время хранится строками `YYYY-MM-DD HH:MM:SS` в локальном времени; длительности считаются суммой интервалов (в SQL через julianday).
- Активна максимум одна сессия. `db.start()` сам ставит текущую на паузу; если есть **paused** сессия той же пары продукт+подзадача — продолжает её, иначе создаёт новую. **stopped** сессии не переоткрываются — возврат к продукту = новая сессия (требование PRD).
- `products.archived` (0/1) — «сдан». Колонка добавлена позже: `Database._migrate()` делает ALTER TABLE для старых баз (CREATE TABLE IF NOT EXISTS новые колонки не добавляет — новые колонки добавлять так же). Сданные не показываются в `product_names()` (подсказки таймера, токены, правка), но есть в журнале/отчётах; в Сводке — чекбокс «Показывать сданные» и ПКМ «Отметить как сданный / Вернуть в работу». `set_archived(True)` завершает открытые сессии продукта; `db.start()` снимает «сдан» автоматически.
- Имена сравниваются через Python `casefold()` (SQLite NOCASE не понимает кириллицу).

## Автообновление (с v2.2.0)
- `DailyCheck` ([update_dialog.py](timetracker/update_dialog.py)): раз в день начиная с `CHECK_AT` = 09:00 (если программа открыта позже — через 3 с после запуска), дальше проверка раз в минуту по часам. Удачная проверка пишет дату в settings `update_checked` (и держит её в памяти); без сети — повтор через 30 мин. Новая версия — окно «Обновить» / «Пропустить» (пропущенная версия — settings `update_skip`, сама больше не предлагается; следующая — снова; ✕ = напомнить завтра). В «О программе» — всегда «Проверить обновления» / «Обновить до X.Y.Z» (там «Позже», пропуск не пишется). Ошибки — понятным текстом (`updater.describe_error`: нет связи / лимит GitHub 403 / нет релиза 404).
- «Обновить»: одна копия базы за запуск (`backup(force=True)`, `Updater.backed_up`) → скачивание zip рядом с exe: только https с `github.com`/`*.githubusercontent.com` (и после редиректов), обязательны размер и sha256 из `digest` GitHub → `TimeTracker.new.exe`. Окно можно скрыть — скачивание идёт дальше; перезапуск делает `DailyCheck._on_prepared` → `finish_update` (ждёт, пока закроют открытый модальный диалог; пауза таймера + `hub.changed`, `timer.restart_exe`, `timer.close()`).
- Три процесса, ни один не трогает свой работающий файл: (1) старая программа выходит обычным путём, main.py после `app.exec()`/`database.close()` запускает `TimeTracker.new.exe --replace <TimeTracker.exe>`; (2) он (`main.run_replacer`, без UI) ждёт mutex до 60 с, копирует себя через `.tmp` + `os.replace` (повторы 20 с — антивирус), отпускает mutex и запускает `TimeTracker.exe --updated`, а при неудаче — старый exe с `--update-failed` (тот показывает сообщение); (3) новая программа ждёт mutex до 15 с, `cleanup()` убирает `.new.exe`/`.tmp`/`.update.zip` (при старте и через 20 с, не трогая идущее скачивание).
- ⚠ **Нельзя переименовывать/подменять exe, пока из него работает программа**: onefile-exe читает свои Python-модули из `sys.executable` во время работы, после подмены импорт падает (zlib error). Первый вариант 2.2.0 так и падал — поэтому отдельный процесс-заменитель.
- ⚠ **Окно обновления не должно отказываться закрываться**: `QApplication.quit()` закрывает все окна и отменяется, если одно отказалось, — программа зависала бы невидимой. Перезапуск поэтому не в окне, а в `DailyCheck`.
- Проверено 15.10.2026 на собранных exe: полная цепочка (пауза таймера, копия базы, замена, удаление `.new.exe`, без сбоев в журнале Windows) и отказ замены (файл только для чтения → старая версия с `--update-failed`). Сценарии окна (трей, мини-окно, модальный диалог, скрыть во время скачивания, «Выход» во время скачивания, ошибка скачивания) — из исходников с подменой `updater.prepare`.
- Из исходников проверка работает, а «Обновить» открывает страницу релиза (`can_install()` = frozen + папка с правом записи, считается один раз). В Program Files и т.п. — тоже страница релиза.
- Сеть — `urllib` (QtNetwork исключён из сборки), без токена: лимит GitHub 60 запросов/час с IP, нам хватает.

## Mac (с 2.4.0)
- Один код: различия только там, где проверяется `sys.platform == "darwin"` / `theme.MAC` / `updater.MAC`. На Windows поведение должно оставаться прежним (стили QSS на Windows сверялись побайтно).
- Значки: Segoe MDL2 на Mac нет → `timetracker/icons.ttf` — подмножество Fluent UI System Icons (Microsoft, MIT, 20 глифов `*_20_regular`, `fontTools.subset`), регистрируется `theme.load_fonts()`; коды `G_*` для Mac в theme.py. Новый значок = добавить глиф в оба набора и пересобрать icons.ttf (полный шрифт: github.com/microsoft/fluentui-system-icons, `fonts/`).
- Размеры шрифтов: пункт на Mac мельче (72 vs 96 dpi) → все размеры через `theme.pt()` (×4/3 на Mac, на Windows без изменений). Новые размеры шрифта — тоже через `pt()`.
- Данные на Mac — `~/Library/Application Support/TimeTracker` (`db.app_dir()`), не рядом с программой: `.app` заменяется целиком при обновлении. CSV по умолчанию — в «Документы».
- Автозапуск — LaunchAgent `~/Library/LaunchAgents/com.rudifreeman.timetracker.plist`; открыть папку — `system.open_path()` (не `os.startfile`, его на Mac нет).
- Мини-окно: `WA_MacAlwaysShowToolWindow` — иначе Mac прячет Tool-окна, когда активна другая программа; `theme.show_on_all_spaces()` после `show()` — на всех рабочих столах (NSWindow.setCollectionBehavior через Objective-C runtime по ctypes, PyObjC в сборке нет).
- Значок Mac — `Icon-mac.png` (сетка Apple: тело 824 из 1024, сглаженная маска, тень), делается `python tools/mac_icon.py` из `Icon.png`; `.icns` из него собирает PyInstaller. Нативный вид Tahoe (Liquid Glass) — только через Icon Composer, не делали.
- ⚠ **Выход на Mac — `QApplication.exit(0)`, не `quit()`**: `quit()` идёт через `NSApplication terminate:`, тот зовёт `exit()` посреди цикла событий → PySide рушится при разборе окон (SIGSEGV в `SenderSignalDeletionTracker`, «неожиданно завершило работу»). Cmd+Q / Dock / выход из системы присылают `QEvent.Quit`, а Qt закрывает только видимые окна → `timer_window.QuitGuard` (фильтр событий приложения) направляет его в `TimerWindow.close()` (пауза с вопросом, поля). Ответ «Отменено пользователем» (-128) на AppleScript quit — обычное поведение Qt, программа при этом выходит.
- Сворачивание на Mac: окно таймера **не прячется**, а остаётся свёрнутым в Dock рядом с мини-окном (спрятанное свёрнутое окно оставляло миниатюру в Dock, клик по ней открывал пустую рамку); развернули из Dock — `changeEvent` прячет мини-окно. `app.setWindowIcon` на Mac не вызывается — иначе Dock показывает icon.png вместо значка из пакета. `theme.show_on_all_spaces` работает только на платформе `cocoa` (в offscreen-тестах winId — не NSView, падение).
- Вылеты собранной Mac-программы: `faulthandler` пишет Python-стек в `crash.log` в папке данных (`main.log_crashes`). Системный отчёт — Console → Отчёты о сбоях.
- Обновление на Mac: `.dmg` → `hdiutil attach` → `ditto` в `TimeTracker.new.app` рядом с текущим → после выхода `/bin/sh`-скрипт (`updater.MAC_REPLACER`) ждёт pid, меняет пакеты местами (`.old.app`), `open … --args --updated` / `--update-failed`. Без права записи в папку программы или при запуске из «Загрузок»/.dmg (App Translocation) — страница релиза.
- Без платной подписи Apple: первый запуск — «Всё равно открыть» в Конфиденциальности (README-mac.txt). Обновления скачиваются программой без карантина и открываются сами.
- Проверить можно только на Mac: снимки окон — артефакт `screenshots`, остальное — раздел 7 QA_CHECKLIST.

## Резервные копии
- `db.backup()` — копия базы (sqlite backup API, консистентно) в `backups/` рядом с базой: `timetracker-YYYY-MM-DD.db` раз в день (при запуске в main.py и при смене даты в `TimerWindow._tick`), «Сделать копию сейчас» → `..._HH-MM-SS.db`. Хранятся последние `BACKUP_KEEP` = 14. Ошибки копирования не должны ронять приложение.
- Восстановление — вручную: закрыть программу, подменить `timetracker.db` копией.

## Ручная правка времени
- Журнал: ПКМ по записи → «Изменить…»; кнопка «＋ Время вручную» в панели журнала.
- Идущую запись править нельзя (сначала пауза). Смена продукта/подзадачи переносит **всю** сессию (все дни) — диалог предупреждает, если дней > 1.
- Нельзя сохранить: конец ≤ начала, конец в будущем, пересечение интервалов между собой или с любым другим интервалом (`db.find_overlap`) — иначе время посчитается дважды.
- Интервалы через полночь в диалоге показаны только для чтения. Не изменённое время (HH:mm) сохраняет исходные секунды.
- Забытое время (`db.add_manual`) идёт в paused-сессию той же пары, если она есть, иначе в новую stopped-сессию.

## Защита от «забытого таймера» (важные правила)
- Дедлайн интервала: `db.deadline_for()` — лимит дня (по умолчанию 18:00); если запущено после лимита с подтверждением (`after_hours=1`) — 23:59:59 того же дня.
- Тик в `TimerWindow._tick`: дедлайн → пауза ровно в момент дедлайна; разрыв между тиками > 5 мин (сон/блокировка) → пауза на последнем тике; heartbeat `last_seen` каждые 15 с.
- При старте `db.recover()` закрывает незакрытые интервалы по `last_seen` (с учётом дедлайна).
- Закрытие окна таймера ставит паузу и завершает приложение; главное окно при закрытии просто скрывается. Сворачивание окна таймера (＿) заменяет его мини-окном (`TimerWindow.changeEvent`), таймер продолжает идти; клик по трею прячет всё. Любой показ окна таймера прячет мини-окно (`showEvent`).

## Соглашения UI
- Все изменения данных → `hub.changed.emit()`; оба окна подписаны и обновляются сами. Не вызывать refresh соседнего окна напрямую.
- Python-данные в item data кладутся обёрнутыми в `delegates.Box` (иначе Qt конвертирует dict/date), читаются через `payload(index)`.
- Иконка приложения: `timetracker/icon.ico` (вшита в exe через `--icon`) и `timetracker/icon.png` (окна, `theme.app_icon()`, кладётся в сборку через `--add-data`). Ярлык на рабочем столе («Time Tracker.lnk») берёт иконку из `dist\TimeTracker.ico` (копируется в build.bat) — иконку exe Windows кеширует и не обновляет. Исходник 1024×1024 — `Icon.png` в корне (сгенерирован пользователем, стиль Apple); ico/png получены обрезкой полей + ресайзом.
- Иконки интерфейса — глифы Segoe MDL2 Assets (`theme.G_*`), без файлов картинок. Для QSS (стрелка комбобокса, галочка) PNG генерируются в temp при старте.
- Журнал: полоса времени дня (24 ч) — светлый отрезок + засечки = рабочий день `db.workday()` (settings `day_start`, по умолчанию 09:00; конец = `limit_time` автопаузы). Настройки → «Рабочий день»: Начало / Конец / галочка автопаузы. `JournalDelegate.workday` выставляется в `JournalPage.refresh`.
- Сводка: `SummaryTree` сам рисует стрелки (`drawBranches`, по центру зоны отступа — QSS-картинки «плавали») и строку-разделитель (`drawRow`, KEY = `SEPARATOR`) между продуктами в работе и сданными. Внизу кнопка «Сдана / Вернуть в работу» для продукта выбранной строки. Выбранная строка сохраняется при обновлении.
- Стрелки дерева в Журнале и Сводке — «›» свёрнуто / «⌄» раскрыто (по просьбе пользователя); колонки Время / Часы / Минуты (целые) / Сессий / Токены / Последняя работа (`SummaryPage.TOKENS_COL`).
- Пользователь просил **компактные строки** (не высокие, как в референсе) и тёмную тему в стиле Windows 11.
- **Термины:** в интерфейсе «Задача» → «Подзадача» (с 2.3.0 по просьбе пользователя: «продукт» путали с подзадачей); в коде и БД по-прежнему `product`/`products`. Слово «задача» в UI — только про product; пару product+subtask называть «подзадача»/«запись»/«сессия».
- Поля Задача/Подзадача в окне таймера — `PickCombo`: только выбор из списка: обычный не-editable QComboBox (тусклый, `combobox-popup: 0` — список вниз), текст ставится `set_text()` (имени нет в списке — поле очищается, **не добавлять**: иначе «Начать» молча создаст переименованную/удалённую задачу заново; поэтому `new_product` сначала создаёт задачу и подзадачу, потом ставит в поля), колесо мыши над полем игнорируется (не переключать задачу незаметно), `set_names()` не трогает список без изменений (иначе refresh закрыл бы открытый список). ⚠ Не перехватывать мышь у комбобокса: версия с editable + открытием по press закрывалась на release и мигала. Анимация выпадающих списков выключена в main.py (`UI_AnimateCombo`) — давала кадр без списка. Новые имена — кнопками «＋ Новая» справа. Запуск из списка подставляет идущую пару в поля (`refresh`: смена активной сессии или её имён — переименование в Сводке).
- «＋ Новая» справа от поля «Задача» → `dialogs.NewProductDialog` (название + подзадача; «Создать и начать» / «Создать»; если имя уже есть — предупреждает и выбирает существующий).
- Список окна таймера = «мои текущие продукты» (`db.work_sessions`): открытые сессии + последняя завершённая сессия каждой пары несданного продукта (серым, «✓ ЧЧ:ММ:СС»). Время в строках = `pair_total` — все сессии пары (с 2.3.1: пользователь видел 00:00:01 у переоткрытой подзадачи и думал, что время пропало); `total` (текущая сессия) — только для больших цифр, подсказки, заголовка окна, мини-окна и трея. Список сгруппирован по продуктам (`TimerWindow._group_rows`, пользователь путал подзадачи с разными продуктами): заголовок продукта (цветная точка, имя, токены, всё время его подзадач, включая завершённые, по одной на пару; не выделяется, клик — подставить продукт, ПКМ — действия продукта) и под ним подзадачи с отступом без имени продукта (`EntryDelegate`, `GROUP_*` в delegates.py). Порядок: продукт с идущим таймером первым, дальше по последней работе. Продукт уходит из списка только по «Сдать». ПКМ по строке: Пауза/Продолжить/Возобновить, Завершить сессию, Сдать продукт, Сводка/Журнал по продукту (`MainWindow.show_product` — всё время, фильтр по имени, раскрыто).
- Окно таймера: одна главная кнопка + «Завершить» (если в полях завершённая пара и ничего не идёт — главная «Возобновить», вторая «Сдать»; режим `restart` в `_intent`). Надпись главной кнопки зависит от полей Задача/Подзадача (`TimerWindow._intent`): Начать (новая сессия) / Продолжить (есть paused-сессия этой пары) / Пауза (эта пара идёт, жёлтая) / Переключиться (идёт другая). Под кнопкой строка-подсказка, что произойдёт. Большой таймер всегда показывает идущую задачу; если ничего не идёт — время paused-сессии из полей, иначе 00:00:00. Пользователь просил, чтобы было видно, начнётся новая сессия или продолжится старая.
- При закрытии окна таймера поля Задача/Подзадача сохраняются в settings (`last_product`, `last_subtask`); при запуске `_restore_fields()` возвращает их (или берёт `db.last_session()`, если сохранённого нет/продукт удалён) и выделяет сессию в списке. Таймер при запуске сам НЕ стартует — только подставляет, чтобы продолжить одним кликом.

## Тестирование
- Автотесты — `tests/` (pytest, `pip install -r requirements-dev.txt`), реестр и правила — [tests/README.md](tests/README.md), ручной чеклист — [tests/QA_CHECKLIST.md](tests/QA_CHECKLIST.md). Фикстуры `db`/`pair`/`at()`/`qapp` в `tests/conftest.py`, Qt offscreen.
- Логику БД удобно проверять с отдельным .db и явными `at=datetime(...)`.
- GUI: можно создавать `TimerWindow`/`MainWindow` с временной БД и снимать `widget.grab().save(...)`.
- ⚠ `QTest.keyClicks` с кириллицей роняет процесс (0xC0000409) — это ограничение QTest, не баг приложения. Для кириллицы слать `QKeyEvent(QEvent.KeyPress, 0, Qt.NoModifier, "б")` через `QApplication.sendEvent`.
- Запускать Python-скрипты из scratchpad с `-X utf8`, иначе консоль ломает кириллицу. Правки с кириллицей через heredoc в stdin Python тоже ломаются — писать скрипт в файл.
