# Тесты Time Tracker

Реестр тестов: как запускать, что уже покрыто и **что ещё нужно покрыть**.
Это живой бэклог — заметил по ходу работы недостающий тест, допиши строку в «🔴 Нужно покрыть»,
не анализируя весь проект заново.

Два уровня проверки:
1. **Автотесты (pytest)** — логика базы, отчёты, окно таймера без показа на экране. Быстро (~3 с), гоняются всегда.
2. **Ручной чеклист — [QA_CHECKLIST.md](QA_CHECKLIST.md)** — то, что видно только глазами и руками
   в настоящем окне: клики мышью, мигание, трей, мини-окно, собранный exe, обновление.

## Правило выпуска

Перед каждой сборкой для себя или коллег (`build.bat`):
1. `python -m pytest` — **все зелёные**. Красный тест = не собираем.
2. Новая функция или исправленный баг → сначала тест на неё в нужный файл (или строка в «🔴 Нужно покрыть»,
   если автотестом не проверить — тогда пункт в QA_CHECKLIST.md).
3. После сборки — по QA_CHECKLIST.md: раздел «0. Дымовой тест» всегда + разделы про то, что менялось.
4. Только потом коммит, тег и GitHub Release (релиз сразу уходит коллегам через автообновление).

Снимки всех окон на тестовых данных: `python -X utf8 tests/screenshots.py <папка>` (не pytest). Сборка для Mac на GitHub делает их на настоящем Mac — артефакт `screenshots`.

## Как запускать

```bash
pip install -r requirements-dev.txt     # один раз: pytest поверх зависимостей программы
python -m pytest                        # весь набор
python -m pytest tests/test_db_timer.py # один файл
python -m pytest -k overlap             # по имени теста
```

Конфиг — [pytest.ini](../pytest.ini) в корне. pytest не входит в `requirements.txt`, поэтому в exe не попадает.

## Инфраструктура — [conftest.py](conftest.py)

- **`db`** — новая пустая база во временной папке на каждый тест. Рабочая `timetracker.db` не трогается
  (тесты можно гонять, пока программа открыта).
- **`pair("Задача", "Подзадача")`** → `(product_id, subtask_id)`, создаёт, если нет.
- **`at(9, 30)`** → 14.10.2026 09:30 (среда), `at(1, day=1)` — следующий день. Методы базы принимают
  `at=` — время в тестах всегда явное, тесты не зависят от часов.
- **`qapp`** — один QApplication на прогон, Qt в режиме `offscreen` (окна не появляются на экране).
- Время «сейчас» внутри `db` можно подменить: `monkeypatch.setattr(dbm, "now", lambda: datetime(...))`.
- ⚠ `QTest.keyClicks` с кириллицей роняет процесс — слать `QKeyEvent` через `QApplication.sendEvent`.
- ⚠ В offscreen выпадающий список (`showPopup`) не становится видимым — открытие/закрытие списков
  проверяется вручную (QA_CHECKLIST) или скриптом с настоящими кликами мыши (см. ниже).

## Проверка кликами мышью (скрипт)

Для поведения, которое в offscreen не видно (выпадающие списки), — скрипт с настоящими кликами через
`user32.mouse_event` и покадровой съёмкой `screen.grabWindow` каждые ~8 мс. Так был пойман и проверен
баг 2.3.0 «список открыт, только пока зажата кнопка / мигает таймер». Двигает курсор пользователя —
запускать, когда за компьютером никто не работает, на временной базе.

## Соглашения

- Комментарии и docstring тестов — на русском; имя теста говорит, что проверяется.
- Каждый тест — своя база (`db`), явное время (`at(...)`), без зависимости от порядка тестов.
- Проверять не только «счастливый путь», но и края: полночь, лимит дня, пустые поля, регистр, кириллица.
- Баг нашёлся → сначала тест, который его ловит, потом исправление.
- Скриншоты найденных ошибок — в `tests/ErrorImage/` (в git не идут).
